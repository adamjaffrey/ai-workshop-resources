# Anonymous Backdrop Contract

This is a mandatory scoped contract incorporated by [AGENTS.md](../../AGENTS.md). Read it before changing the behaviours it covers. Paths and commands in code spans are relative to the repository root. Documentation-only work does not trigger the software checks listed here.

## Blur Placeholder Geometry

- Follow the block sizing, colour and preview rules in `website/README.md`, under “Block Geometry Rules”.
- Use invisible lowercase `x` characters only for eligible words inside prompt/code text (`pre`) and skill-slug labels (`.slug`). Do not apply this technique to every monospaced text area. A word is eligible only when every original character has the same rendered width as `x` in that text style, within the generator's tolerance of less than 0.01px per character.
- For each eligible word, retain `/` and `-` and replace every other character with `x`; preserve the original whitespace between words. Make these anonymous glyphs transparent and draw the visible cap-height blocks with CSS. The glyphs are layout scaffolding, not visible lettering or protected text hidden by blur.
- Preserve native browser wrapping with these glyphs: long prompt words, commands and skill slugs can split across lines as the viewport changes. One measured rectangle per word is unbreakable and cannot reproduce those internal line breaks. Retaining slash/hyphen punctuation preserves the corresponding native break opportunities; do not replace entire prompt lines with fixed bars.
- Use measured empty rectangles for all text outside `pre` and `.slug`, and for any word inside those areas that fails the equal-width check, including wider emoji. Measure each word in its actual font/style after fonts load; retain its measured width, spacing and line-box dimensions. Both approaches use the same cap-height and baseline rules. When a source line box is shorter than its glyph bounds (for example, a `1cap` caption), keep the measured glyph rectangle but compensate its inline-block margins and alignment so the replacement does not enlarge that line box. In Playground explanatory prose, split measured filename/path rectangles at existing slash/hyphen break opportunities so those native breaks remain available; this does not extend dummy `x` glyphs beyond `pre` and `.slug`.
- Never include original protected words, commands or link destinations in the generated backdrop. Removing the blur or making the anonymous glyphs visible must reveal only measured shapes and dummy text. These eligibility and replacement rules are implemented in `website/scripts/measure-placeholder.mjs`, with block styling in `website/lib/workshop-placeholder.mjs`.
- Keep separate saved geometry for Resources (`website/lib/workshop-placeholder.generated.json`) and Colours (`website/lib/workshop-playground-placeholder.generated.json`). A new backdrop needs an initial capture to create its geometry; this does not authorise routine remeasurement of existing backdrops during internal builds.
- Remeasure an existing backdrop only when preparing an explicitly authorised Sites publication AND layout changes since the latest successful Sites publication affect that backdrop. Internal builds and local previews reuse saved geometry even when a layout revision is pending; do not remeasure merely to make an internal build current. Do not run browser measurement automatically during development/build startup.
- Before publishing, query Sites for the latest successful deployment, resolve its saved version and exact source commit, and inspect that source checkout. Do not assume the latest saved version, local HEAD or latest GitHub push is live. Compare that committed website source with the candidate, including intervening internal builds and uncommitted changes. Review the actual diff for effects on visible Resources and Colours geometry; document-only, colour, strength, blur, authentication and animation-timing changes alone do not require measurement.
- Relevant layout changes include structure, positions, dimensions, spacing, fonts, weight/size, letter spacing, line height, wrapping, breakpoints, word geometry, icon sizes and QR pattern bounds/padding. Text or asset edits count only when those measurements change. Footer-only edits below the visible backdrop and version-label edits with identical geometry do not require measurement. If the published source cannot be verified, resolve that uncertainty before publication rather than guessing a baseline.
- Mark affected layout changes with the corresponding `placeholderLayoutRevision` or `playgroundPlaceholderLayoutRevision` in `website/lib/workshop-layout.mjs`. These are independent geometry cache keys, not artefact versions. At publication preparation, after all layout edits, run `npm --prefix website run blocks:measure` for affected Resources geometry and `node website/scripts/measure-playground-placeholder.mjs` for affected Colours geometry. Other tabs may be captured only for an explicitly requested comparison, following the comparison rules below. No additional approval is required within an authorised publication.
- Run `node website/scripts/check-placeholder-publication.mjs --published-source PATH --published-commit SHA` using the verified source checkout and full Sites commit. Review its source-change list and require saved revisions to match before publishing. This check does not infer layout changes from filenames or source fingerprints: the reviewed diff determines whether a revision/refresh is needed. Validate and commit refreshed geometry with the publication candidate. A failed publication does not advance the published baseline; reuse already validated candidate measurements when their layout inputs remain unchanged.
- Preserve the main backdrop's glyph/rectangle rules above in the Playground capture and its visible specimens. Capture the Style Inspector as a static final section at the bottom, with neutral content and its details expanded; remove its floating dock positioning, shadow and reserved viewport spacing. Retain the interactive dock in the authenticated Playground. Remove protected text, source actions and inactive tab bodies; retain responsive layout and measured word/icon shapes. Backdrop frames have no scripts or interactive access. Their saved geometry is generated locally, never measured in a visitor's browser.
- Run the archived `test:blur-preview` only when explicitly requested. Generating preview HTML is separate from measurement; source fingerprints record provenance and do not independently trigger refreshes.

### Static Capture Behaviour and Rationale

- Treat a login background as one fixed composition in document coordinates, not an interactive page. Here, “fixed asset” does not mean CSS `position: fixed`: scrolling the block inspection view must move captured controls with the page, without persistent hovering silhouettes that reveal the underlying page structure throughout the scroll.
- Before every future login-background geometry measurement or snapshot, normalise viewport-fixed positioning to document-anchored positioning and sticky positioning to normal document flow. Disable hover, active and focus-state styling, animations, transitions and scroll-driven state changes in the capture. Preserve initial responsive geometry and the existing cap-height, baseline and wrapping rules. Clear sticky inset offsets as well as sticky positioning so a discarded `top` offset cannot shift the static capture. Never change the real app or Playground's interactive behaviour to prepare a decorative capture.
- For the Playground backdrop, keep the top-right tools anchored to the captured document and place the Style Inspector last in normal flow. Capture its expanded neutral state; do not retain live inspection readings, floating shadows or bottom viewport reservations. Apply the same static preparation to embedded specimens. Use `website/scripts/prepare-backdrop-capture.mjs` for this preparation and verify that no captured element remains fixed/sticky or changes on hover.
- Active Resources and Colours captures contain no nested specimen iframes. Use `website/scripts/capture-backdrops.mjs` at exactly 380, 660, 940, 1008 and 1248 CSS pixels with a normal 1000px viewport height; inspect full document height without enlarging the viewport. Save one responsive DOM with metric overrides only for words that change across these widths. Native CSS controls intermediate wrapping and normal container growth; never scale the entire capture or freeze whole prompt lines. No every-pixel height sweep, runtime measurement or routine +1px capture is required.
- Preserve each original text node as one anonymous text item inside flex/grid layouts. In particular, keep disclosure-label word blocks inside one wrapping span beside the chevron, not as separate grid cells. This is a structural correction and does not require remeasuring saved word widths.
- Freeze the settled visible state. Preserve hidden/invisible icon layers when replacing SVGs; an inactive loading/success layer must not become a visible block. Keep responsive CSS visibility separate from fixed control state. Lock scrolling without changing native text wrapping, and preserve intentionally bounded prompt windows.
- Routine geometry validation uses the same five widths, with a small anonymity/state regression check and relevant login/shortcut checks. Accept minor decorative positioning differences. Detect missing content, gross clipping and reactivated state layers; do not require exhaustive word-coordinate parity. The opt-in `compare-backdrops-once.mjs` diagnostic compares 381/661/941/1009/1249px with reflowed captures from 660/940/1008/1248/1440px. It is a migration check, never a routine build/capture dependency.
- Captured documents remain anonymous and script-disabled. Blocks and Blur may expose outer-document native scrolling to inspect them, but must not restore original actions, hover states or sticky behaviour. Verify that tool silhouettes leave the viewport when scrolled and the inspector appears only at the bottom.
- Keep preview viewports constrained to their containing card's optical rails, including expanded views. A selected desktop Screen Width enlarges the iframe inside that viewport, not the surrounding viewport itself. In isolated specimens only, allow horizontal scroll chaining through the login overlay and root; retain production login containment and vertical behaviour. Preserve native horizontal and vertical scrolling; test touch gestures beginning inside the iframe, not only programmatic `scrollLeft` changes. Do not add gesture interception or disable vertical scrolling when a sizing correction resolves overflow. Test narrow phones, wide selected widths, Fit, and inline/expanded views; distinguish emulated touch from physical-device verification.

### Interaction and Scrolling Policy

- Both anonymous backdrops use the default arrow throughout. Disable hover, active, focus, selection, dragging, resizing and animation feedback; retain inert content and script-disabled captured frames. Apply the same static policy when creating captures and when rendering previously saved geometry, without remeasuring word dimensions.
- Decorative capture frames remain outside sequential keyboard navigation in every inspection mode. In both Resources and Colours inspection, only the document root owns overflow; keep the body non-scrolling and captured descendants inert. Render both captures through the same inspection iframe and controller directly under the Playground in a same-origin, script-disabled sandbox, so the existing enclosing keyboard stop can scroll its root without focusing the capture. Only the saved anonymous source content varies by destination. Reuse the shared footer-wrap helper where that content includes a footer. Keep the interactive login specimen separate and locked for Password Panel mode; it must not retain a second scrollable inspection path. Support arrows, Page Up/Down and Home/End; horizontal arrows retain access to a selected wide viewport. Use one parameterised regression for both destinations: verify keyboard and native wheel input inline and expanded on desktop/mobile widths, plus emulated touch starting inside the frame.
- In Blocks and Blur, allow only the outer inspection document to scroll in No Blur and Blur and Darken. Keep nested captured documents, controls and prompt areas locked, including captured login specimens. Never recursively remove inertness or enable pointer access in embedded frames. Remove block-click selection; the real controls outside the preview remain interactive.
- Password Panel mode resets and locks the inspection background. Actual login panels retain keyboard access and their own scrolling for short viewports. Captured login dimming covers the entire captured document, including content beyond its initial viewport; it remains separate from the single background blur.
- Preserve responsive widths and normal text wrapping; ordinary containers must grow with their contents. Lock existing overflow containers without imposing fixed content widths or replacing wrapped text with fixed lines. Test narrow and wide layouts, nested cursor/hit-target suppression, full-document dimming and switching between scrollable inspection and locked panel modes.
- Preserve the parent login page’s coordinate-based Wavelength shortcut. It must not restore pointer targets, focusability or cursor feedback inside the anonymous capture.
