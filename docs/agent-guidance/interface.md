# Interface Contract

This is a mandatory scoped contract incorporated by [AGENTS.md](../../AGENTS.md). Read it before changing the behaviours it covers. Paths and commands in code spans are relative to the repository root. Documentation-only work does not trigger the software checks listed here.

## Focus and Panel Opening

- Use `--focus-sharp-radius: 1px` as the base radius for intentionally sharp focus corners, including both prompt upper corners and URL Reference code focus; the tab-bottom comparison below is an explicit outer-radius exception. Preserve intentionally rounded controls, link highlights and non-focus decorative shapes. Keep the shared 3px outline offset and 3px ring thickness.
- Border-based Playground overlays use `--focus-sharp-outer-radius`, derived from the base token plus the shared gap and ring thickness, rather than applying the base token directly at the outer edge. Prompt overlays continue copying their canonical app pseudo-element’s outline, offset and radii. Preserve the existing rounded overlay calculations. The outer Playground tabs use only their sibling group-focus ring; do not add a separate tab-specific overlay geometry branch. For the current user-requested comparison, keep the native 8px-base upper outline unchanged and paint the lower half with a 3px border at the same 3px clearance, using the sharp token as its 1px visible outer radius. Overlap the two clipped straight-side halves by 1px to avoid fractional clipping seams. This is a tab-only comparison; other sharp rings retain their base-radius meaning.
- Keep real focus on the appropriate control for every interaction type. Do not blur controls or remove keyboard access merely to hide a ring.
- Text-entry fields, including passwords, retain visible focused styling for pointer, touch and keyboard use.
- Buttons, toggles, links and other non-text-entry controls show a focus ring only during keyboard navigation initiated by Tab or Shift+Tab. Preserve that indicator through keyboard activation and focus transfer; click or tap switches back to ring-free pointer focus.
- Theme, agent, Playground segmented selectors and tab bars each have one Tab stop. Use the shared `workshop-group-focus.mjs` controller: arrows and Home/End browse focus without changing the value, panel or URL; Enter/Space activates. Show the existing grey hover treatment on the keyboard-focused option, preserving selected styling on the active choice. Tab leaves the group; re-entry starts at its selected option. Playground sections themselves have no Tab stop.
- Keep selector and tab focus rings 3px thick with 3px exterior clearance. Playground scrolling groups use an unmasked sibling ring following the focused option, outside the inner scrolling track; never inset the ring or let the fade mask clip it.
- Reveal the QR Copy Link overlay immediately on keyboard focus, with no delayed fade. Preserve existing pointer/touch reveal and copy-feedback timing.
- After a segmented selector changes, focus the newly selected mode for mouse, touch and keyboard activation, including activation from track padding or gaps. Apply the same rule to agent and day/night selectors.
- On opening any modal, dialog or popover panel, focus its descriptive heading with `tabindex="-1"` and prevent scrolling. The heading must never display a focus ring, regardless of input method. Do not initially focus a text field or open the software keyboard. Style Options follows this same heading-first rule.
- The Playground Style Options menu is visually a popover but uses native modal dialog containment. While open, block background interaction and scrolling. Close with X, Escape or an outside tap without activating the background, then restore the previous scroll position. Hide its button focus ring throughout both opening and closing animations; on opening retain silent heading focus and make the next Tab reach X; on closing restore the ellipsis button only after the animation. Pointer activation remains ring-free; keyboard activation restores the ring only after the transition.
- The first Tab after heading focus must reach the first visible, enabled interactive element in logical DOM order and display its keyboard focus ring. Preserve the login order: day/night selector as one stop, password, then unlock.
- Use the shared panel-heading focus helper for custom panels and the shared opening handling for native dialogs/popovers. Every such panel must have an accessible heading. Preserve native modal containment and focus restoration to the invoking control when a panel closes.
- Validate initial/opening focus, Tab/Shift+Tab navigation, keyboard activation, pointer/touch ring suppression, input focus and selector destination focus on desktop and mobile layouts when modifying these flows.

## Cursor Behaviour

Follow [Uxcel: Types of Cursors & When to Use Them](https://uxcel.com/lessons/basics-834) as the reference for future cursor decisions. Match the cursor to the action available at the hovered location.

- Use `cursor: pointer` (hand) for all enabled buttons, toggles, links and other clickable or activatable elements. Apply it across the complete hit target, including icons, labels, selector tracks, padding and gaps; the cursor must change immediately on hover.
- Use `cursor: not-allowed` for disabled, blocked or unavailable controls, including controls marked `aria-disabled="true"`. This state takes precedence over pointer or text cursors. Cursor styling does not disable an action: also enforce the blocked behaviour and appropriate disabled semantics.
- Use `cursor: text` (I-beam) for selectable text and text-entry/editing fields, including body copy, prompt/code text, password inputs and textareas. Text and icons inside clickable controls are part of the action, not independent text-selection targets. Over an enabled button or toggle, the icon, label text, background, padding and gaps must all show the same hand cursor; label text must never switch to an I-beam. If that control is disabled or blocked, every one of those areas must instead show the not-allowed cursor. Reserve the I-beam for independently selectable or editable text outside action controls.
- Use the default arrow for noninteractive, nonselectable surfaces. For specialised interactions such as dragging, resizing or precision selection, follow the reference's action-specific cursor guidance.
- Preserve these distinctions in normal, hover, focus and disabled states. Do not use `pointer-events: none` merely to style a disabled control if it prevents the intended not-allowed cursor from appearing.

## Optical Alignment Contract

Use the shared two-rail layout in `website/lib/workshop-alignment.mjs` for every active surface: Resources, both login destinations, all Playground tabs, grey specimen interiors, menus, dialogs, overlays, inspectors and expanded previews. This supersedes the earlier rule that independently inset selected labels and excluded specimen interiors.

### Why

Rounded corners visually recede from their bounding edge, while SVG icons can contain invisible whitespace. We selected a 4px surface extension through visual comparison. This is a project design convention, not a universal design standard. Shared rails replace per-element judgement calls and preserve a minimum 24px mobile surface gutter.

### Deterministic Rules

- Each layout scope defines a text rail. Text, square-edged objects, tables, rules and square textareas start on this rail. Page headers, branding groups, dialog headings and introductory copy follow it too.
- Designated rounded boundary components extend 4px outward from that rail. Full-width surfaces extend on both sides; intrinsic-width controls extend from their aligned edge. On mobile page layouts, the surface rail is 24px from the screen and the text rail is 28px. Expanded views use the same rails. Centred elements remain centred.
- Use the single `--optical-offset` token. The component selectors in the shared module register existing scopes and surface boundaries. New scopes can use `.alignment-scope` with `--surface-padding`; full-width rounded children can use `.alignment-surface`. Square/text children stay on the scope's text rail. Do not automatically select all elements with a border radius.
- In Playground specimen galleries, use one 28px text rail and 24px rounded-surface rail measured from the grey frame interior. `website/lib/workshop-specimen-layout.mjs` is the sole gallery-layout owner, injected once after canonical component styles. It uses the shared rail tokens; do not add gallery offsets in the page generator or shared app alignment sheet. Gallery documents own this inset; iframe wrappers and specimen rows must not add horizontal padding. Scrollable specimen viewports extend through the existing grey gutter with compensating margins and padding, retaining room for focus rings and outdents without narrowing the content again. Keep optical corrections in `--specimen-optical-nudge`, applied to the specimen itself, never added to viewport padding. Remove captured page-positioning state before applying them. Measure visible focus edges separately from control border boxes: the selector track starts at 25px while its outer ring starts at 24px. Non-scrolling specimens allow paint into that gutter; keep all paint inside the outer rounded grey frame and never onto the white section. Do not mask complete login contexts or their shadows. Full-page iframe specimens retain native page gutters without an extra wrapper inset. Preserve these relationships in expanded views and refresh control measurements when revealing previously hidden frames.
- Keep gallery row separators as the single divider source. Apply H3 top dividers only inside URL Reference; do not add global H3 borders to specimens. Use a shared 32px vertical separation above and below Playground control groups, including selectors, action buttons, checkboxes and sliders; adjacent groups share one gap. Retain 16px between selector labels and their controls, and preserve the 40px gap after the Resources agent selector. Slider labels and values use the selector-label font (14px/21px, weight 600). Keep slider hit targets 44px tall but use a 4px CSS label gap, giving approximately 16px to the visible thumb. Slider grids use the Playground Icons 280px minimum columns and 32px horizontal gap, capped at three columns, with 32px between rows. Place adjacent multi-option selector groups in wrapping rows at natural widths, separated horizontally by 32px between visible rounded surfaces (use a 36px layout gap to compensate for their 4px optical extension); do not shrink groups to force them onto one row.
- Pin mobile tabs at the top, with Style Options then Back to Top stacked vertically on the right below them, separated by 8px. Move tools with scroll position into a resting position 12px below the tab bar. Keep the normal 16px panel gap below mobile tabs; do not reserve extra flow space for the floating tool stack. Preserve desktop sticky controls and their 1px divider. Fade toolbar legends over the final 64px before pinning and make them fully transparent while pinned. Fade in a background extending above the mobile tabs over the final 64px before pinning to cover translucent browser chrome. On mobile, make the actual sticky tab ancestor viewport-wide with an opaque page-colour background, while keeping its inner tab rail and baseline aligned to panel surface edges. WebKit edge sampling examines the hit-tested element and its ancestors; a full-width background sibling behind a narrower sticky container is insufficient. Keep desktop geometry unchanged. Tab selection lands at the start of the pinned region with the page header scrolled away. Keep white Playground panels 16px apart. Horizontal control strips must allow vertical scroll chaining while remaining vertically locked.
- Share compact prose-list styles through `website/lib/workshop-body-type.mjs`: 20px hanging indentation, markers near the text rail, and one extra indent per nesting level. Demonstrate wrapped and nested lists in Typography. Render element/class/ID references and source filenames in monospace. Keep all applicable selectors, checkboxes, sliders and action buttons available in expanded previews, restoring them on close.
- Use the same theme-aware hover fill for unselected agent/theme options across Resources, login, Playground and compact controls: darker in light mode and lighter in dark mode. Paint hover fills below the animated selection indicator and labels above it, including during press/hold and travel. Keep selected options unchanged. Prompt copy buttons retain their original `--hover` fill. Align disclosure body copy with its summary text. Keep segmented-selector legends on the normal text rail and preserve native button interior spacing.
- Apply the extension once per component boundary. A button inside a toggle does not acquire a second outward offset. Nested cards and prompt panels establish their own text rail using their normal interior surface spacing plus 4px; their designated rounded children may extend back to that interior surface rail.

### Scrollable Control Style and Validation

- Treat tabs, horizontally overflowing menus, toggle selectors and other one-row selection regions as horizontal-only scrollers. Hide vertical overflow, keep the content tall enough for its controls and keyboard focus treatment, and verify that it cannot acquire a vertical offset. Do not disable page scrolling or trap vertical touch gestures merely to lock the control's own axis.
- Use `overflow-x: auto`, not forced scrollbars, where content can exceed its container. Preserve horizontal access at narrow widths, with longer labels and enlarged text. Fitting content must have no horizontal movement or unnecessary scrollbar. Do not use clipping or `overflow-x: hidden` as a substitute for making all options accessible.
- Use the shared 54px horizontal feathered edge mask, including an 18px low-opacity shoulder; tab bars and segmented selector rails use a wider 108px feather with a 36px shoulder, and scroll-distance state handling. Each edge reaches full strength over 18px of travel away from its boundary, rather than on a time-based animation. - When adding or changing a control, check narrow phones, tablet/desktop widths and breakpoint boundaries; start, intermediate and final horizontal positions; reverse scrolling; resize from overflowing to fitting; longer labels and enlarged text; keyboard navigation/selection, pointer and touch input; focus-ring clearance; and inline, sticky, expanded and iframe states where applicable. ## Text Links, Anchor Links and Hover States

These are global website rules for current and future text links and anchor-copy controls, including their Playground specimens. Reuse the shared implementation; do not create page-specific spacing or decoration variants.

Use explicit modifier classes to select navigation icons: `.workshop-link--internal` selects Modified Arrow Right and `.workshop-link--external` selects Modified Arrow Up Right. Only the two Skip to Main Content links are marked internal in this change. Do not infer icon choice from label text, `.skip-main`, or automatic URL classification.

- **Anchor icon placement follows the text’s actual alignment:** right-aligned text receives its Hash icon on the left; all other text receives it on the right, including left-aligned, centred and justified text. Re-evaluate the side when alignment changes responsively. This is a general rule, not an exception tied to Step 2 or desktop. Reserve the icon slot on the appropriate side even while hidden so hover and feedback never move the label. Keep the label on its intended alignment rail. Check and X occupy the same side and slot as Hash. Navigation-link arrows remain after the linked text; the side-switching rule applies to anchor icons.
- Use the shared inline link treatment in `workshop-links.mjs` and proportional icons in `workshop-link-icons.mjs`. Set link and anchor layout padding to zero. Native `box-decoration-break:clone` repeats the solid background and zero-blur box shadows on every wrapped line. Paint extends 0 top, .125em right, .05em bottom and .075em left without affecting text alignment, spacing or wrapping. Keep the base .2em radius. Do not measure line fragments or use a single positioned pseudo-element for these backgrounds. Standalone Playground links use normal text alignment without compensating negative margins. The painted extension is separate from the text box; do not reintroduce padding to create it.
- Regular hyperlinks retain a resting underline with automatic thickness and ink skipping at .1em offset, hiding its colour on hover; show the approved Modified Arrow Up Right persistently, except the two page-level Skip to Main Content links, which use Modified Arrow Right for their internal destination. Anchor-copy labels have no underline at rest or on hover; hover reveals the background and modified Hash. Both use shared accessible link ink. Paint the solid theme-specific hover fill immediately so overlapping fragments never alpha-compound, including during entry/exit. Text, underline, background and Hash opacity change instantly, with no hover transition. Preserve keyboard focus and existing copy-result timing.
- Keep a trailing icon with the final word in a non-wrapping tail; keep a leading anchor icon with the first word (or keep the complete short label together), using a .2em CSS gap for all navigation links and anchor-copy icons on either side rather than adding a second literal space. Reuse the shared `textIconGap` value; do not define separate left/right or hyperlink/anchor gap values. Always reserve a 1cap slot, including when an anchor icon is hidden. Use the lab's common 24-unit SVG canvas at 1.2cap and a .08em stroke converted to viewBox units, multiplied by 1/1.3/1.5 for regular/semibold/bold text. Centre the canvas at the cap-height centre. Hash, Check and X share exactly the same slot, dimensions and gap; preserve their original internal geometry rather than independently stretching each symbol. The user-approved modified Hash, Modified Arrow Up Right and Modified Arrow Right are explicit Lucide derivative exceptions; retain the original official names, variant metadata and Lucide licence/source links.
- Copy success shows Lucide Check using the theme's success token; failure shows Lucide X using the error token. Visible anchor confirmation text is limited to an icon tooltip, with an assistive-technology announcement. Follow [Shared Success and Failure Feedback](#shared-success-and-failure-feedback) for motion, hold durations and future reuse.

Keep semantic success/error colours distinct; do not introduce local colour variants. Check normal-size link ink at a minimum 4.5:1 against the hover fill.
- Hover styling is immediate on entry and exit; copy-result animations are separate and retain the durations, easing and fully visible holds in [Shared Success and Failure Feedback](#shared-success-and-failure-feedback). Preserve keyboard focus indicators, accessible names and result announcements. Icons remain decorative when the control already has an accessible name.

## Title Case

Use **The Chicago Manual of Style, 18th edition (CMOS 18)** as the website's title-case standard, specifically paragraphs 8.160–8.162. Consult the [official title-case Q&A](https://www.chicagomanualofstyle.org/qanda/data/faq/topics/CapitalizationTitles.html) and [18th-edition changes](https://www.chicagomanualofstyle.org/help-tools/what-s-new.html) when a grammatical role or compound is ambiguous.

### Categories

Apply this standard to:

- Browser/page titles and all visible page, dialog, section, card and table headings, including `website/URL-REFERENCE.md`.
- Subheadings, step subtitles, pre-headings and heading-like captions.
- Button and action labels, including temporary states, icon-button tooltips and equivalent accessible names.
- Input-field labels, selector/toggle labels, control-group labels and prompt-panel header labels.
- Raw text for labels displayed in all caps by CSS, including textual wordmarks where official brand styling permits.

### Rules

- Capitalise the first and last words of each title or subtitle, and the first word after a colon introducing a subtitle.
- Capitalise nouns, pronouns, verbs, adjectives, adverbs and subordinate conjunctions. Determine a word's grammatical role rather than lowercasing every short word; adverbial particles in phrasal verbs remain capitalised.
- Within a title, lowercase articles (`a`, `an`, `the`) and the coordinating conjunctions `and`, `but`, `for`, `or` and `nor`.
- Lowercase prepositions of four letters or fewer; capitalise prepositions of five letters or more, as specified in CMOS 18. Lowercase `to` when it marks an infinitive, and lowercase `as` in any grammatical function, subject to the first/last-word rule.
- Apply CMOS 18's compound rules to hyphenated terms: capitalise the first element and subsequent principal elements, including those following a prefix, while retaining lowercase articles, short prepositions and coordinating conjunctions where required. Capitalise the second element of spelled-out hyphenated numbers and fractions. Preserve established proper-name styling.
- Preserve the official casing of brands, acronyms, technical identifiers and name particles; retain specialised conventional lowercase forms where CMOS requires them. Do not alter commands, code, filenames or skill slugs to satisfy title casing.
- Store correctly cased source text. Use CSS uppercase only as a visual treatment; do not use CSS capitalisation or a blanket short-word list as a substitute for a grammatical audit. Audit dynamic label states and both agent choices as well as initial text.
- Keep body paragraphs, explanatory copy, full-sentence accessibility descriptions, status/error messages and code content outside these title-case categories unless they independently serve as headings or control labels. Keep this contract focused on categories and rules, not an inventory of individual interface strings.
