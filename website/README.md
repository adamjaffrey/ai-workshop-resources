# Workshop Website Access

The server verifies the shared password before returning workshop content. Sessions expire seven days after login without extending on use. The persistent Secure, HttpOnly, SameSite cookie survives tab and browser closure, unless the user clears cookies or uses private browsing. Logging out revokes the current session immediately; changing the server verifier invalidates all existing sessions.

## Configuration

Keep the chosen password in the repository root's ignored `.env` as `password`. Never copy it into source, client assets, command arguments or Git. Production uses only the secret `WORKSHOP_PASSWORD_VERIFIER`, generated by `makeVerifier` in `lib/workshop-handler.mjs`, using scrypt and a random salt. Treat this verifier as secret too. Updating the local file alone does not change the deployed site: securely update the hosted secret and deploy the validated build.

`.openai/hosting.json` retains the existing Site ID and declares the D1 `DB` binding. Sites applies the checked-in Drizzle migrations during deployment. The database stores hashed random session tokens, expiry timestamps, verifier versions and short-lived attempt counters. No plaintext password or session token is stored in D1. Missing configuration or database errors deny access.

## Build And Validation

Use Node.js 24 or later for the built-in SQLite tests. This application retains the supported Sites Vinext starter and build integration. Install dependencies with `npm run install:ci`, configure the local execution profile with the Sites plugin's `configure-execution-profile.mjs`, and build with its `build-site.mjs`. Run `node --test tests/auth.test.mjs` before building.

For local Worker testing, apply `drizzle/0000_early_felicia_hardy.sql` to the local D1 database, provide a test-only `WORKSHOP_PASSWORD_VERIFIER` in ignored `dist/server/.dev.vars`, then run `npm start -- --port 8787`. The browser check uses the test password declared in `tests/auth.test.mjs`. Run `node tests/browser-check.mjs` with Playwright available, or set `PLAYWRIGHT_MODULE` to its absolute module location. The test uses installed Chrome. Rebuilds remove the local `dist/server/.dev.vars`; restore the test verifier and restart the preview after rebuilding. Remove local secret files before packaging.

The tests cover unauthorised content delivery, forged cookies, fixed seven-day expiry, password rotation, logout revocation, origin checks, request limits, rate limits, unavailable dependencies, browser restarts and mobile layout. Login attempts are limited to 50 per source IP and 1,000 globally per 15-minute window. Participants behind one shared network share the IP allowance.

## Access Boundary

This protects content delivered by this website. The linked public GitHub repository, its history and independently published files remain public. A shared password can be forwarded and does not identify individual participants. Branding assets remain public; workshop content is delivered only by the authenticated server route. Previously downloaded material cannot be withdrawn.

## Local Design Review

Run `node website/scripts/measure-placeholder.mjs --if-needed` followed by `node website/scripts/preview-login.mjs` from the repository root, then open `website/outputs/login-design-preview.html` directly in Chrome. The first command reuses valid measurements without launching Chrome; the second regenerates the standalone HTML. No server is needed. The form is disabled, and the preview contains no credentials or protected workshop content. Output files are ignored by Git and excluded from deployment.

Switch between No blur, Blur only and Password panel. Block strength ranges from 0% to 100%, initially 40%. Background blur ranges from 0px to 20px in 0.5px steps, initially 5px. Both sliders update independently and can be adjusted together. No blur temporarily removes the background blur while retaining its slider value; switching back restores that value. Password panel retains its additional 7px backdrop blur. Slider changes are local to the preview, reset when reloaded, and do not persist production settings.

Run `node website/scripts/preview-resources.mjs` from the repository root to generate `website/outputs/workshop-resources-preview.html`. Open it in Chrome. Images and the font are embedded so previews work when moved. The resources preview retains the agent selector and copy controls but omits session checks and logout. Keep design iterations local until publishing is approved.

## Block Geometry Rules

### Words And Text Styles

- Replace every visible word separately, including prompt text; do not estimate widths from character counts or replace entire prompt lines with generic bars.
- Measure rendered word widths in Chrome after the page font has loaded. Retain the measured widths, original spacing, line boxes and responsive wrapping.
- Use one consistent cap height per text style, measured from capital H at that style's font family, weight and size. Align each block's bottom to the alphabetic baseline. Do not use average word height or each word's ascenders/descenders; emoji placeholders follow the same cap-height rule.
- Monospaced words use invisible anonymous glyphs to preserve native wrapping, including words that span lines. Wider exceptions such as emoji use measured boxes. Never include the original protected words in the generated login geometry.

### Icons And QR Code

- Replace background SVG icons with blocks. Group the step icons, agent logos, theme icons and copy/success icons separately; match dimensions within each set using its largest measured width and height. Include CSS dimensions for hidden state variants.
- Current set dimensions are 26×26px for step icons, 20×20px for ChatGPT/Claude logos, 20×20px for theme icons and 18×18px for copy/success icons. These describe the present layout; future layout measurements determine new values.
- Preserve each icon's layout classes, alignment, surrounding tile/button, responsive visibility and spacing. Keep the Wavelength branding image visible. Functional password-panel controls remain functional and are not replaced.
- Replace only the QR pattern with one block. Measure the original dark-pixel bounds and preserve the surrounding opaque white quiet zone. The present 540×540px source has 48px padding on each side, scaled proportionally with the image. Keep that padding white in both themes; retain the QR card, caption, border and responsive visibility.

### Colour And Blur

- Default block strength is 40%: an opaque mix of 40% foreground ink and 60% of the containing surface colour. This is a colour blend, not element or page opacity.
- Use the relevant surface for each word/icon: page, card, prompt panel, button or icon tile. Preserve those surfaces and their colours. For the QR centre, mix dark ink with white and leave its white padding untouched.
- Apply the same Block strength setting to words, icons and the QR centre. Retain the separate 5px background blur default. Do not bake strength or blur into measured geometry; changing either never requires remeasurement.

### Reuse And Remeasurement

Website changes that preserve layout reuse the existing geometry. Colour, strength, blur, interaction timing, authentication, documentation and preview controls do not require remeasurement unless they also change resting dimensions or positions. Layout changes include structure, spacing, fonts, text metrics, wrapping, breakpoints, changed word geometry, icon dimensions and QR bounds/padding.

For a layout change, increment `placeholderLayoutRevision` in `website/lib/workshop-layout.mjs`. Development/build startup runs `measure-placeholder.mjs --if-needed`, which measures only when that revision differs from the generated geometry or the geometry is missing. Without a layout change, it skips measurement and regenerates the preview HTML from the existing blocks. After edits in an already-running development session, run the same conditional measurement command and regenerate the preview HTML, then reload Chrome. The direct measurement command without `--if-needed` forces regeneration and should be reserved for an actual geometry update.

`website/scripts/measure-placeholder.mjs` uses installed Google Chrome through the Playwright development dependency and saves anonymous markup in `website/lib/workshop-placeholder.generated.json`. The stored source fingerprint records provenance only; it does not invalidate measurements for unrelated source changes. The renderer rejects a mismatched layout revision. Measurement runs during preparation, never in a visitor's browser. `workshop-resource-page.mjs` owns the resource template independently of the login renderer. Original text, links, scripts and action attributes are excluded from the login markup, which remains inert and hidden from assistive technology.

### Validation

Run `node --test website/tests/placeholder.test.mjs` for content removal and layout-revision checks. Run `node website/tests/word-geometry-browser-check.mjs` for word positions and widths within 1px at four viewports, cap heights/baselines, matched icon sets, QR padding and both sliders. `node website/tests/placeholder-browser-check.mjs` covers themes, overflow and the password panel. Geometry comparisons use the build machine's fonts; other operating-system fonts may differ slightly. Run relevant checks for the change rather than remeasuring unchanged geometry.

## Agent Logos And Colours

The agent selector pairs the ChatGPT knot logo with “Codex” and the Claude starburst logo with “Claude Code”. The inline SVGs come from [Lobe Icons’ OpenAI SVG](https://github.com/lobehub/lobe-icons/blob/master/packages/static-svg/icons/openai.svg) and [Claude SVG](https://github.com/lobehub/lobe-icons/blob/master/packages/static-svg/icons/claude.svg). Both inherit `currentColor`, remain decorative to assistive technology and retain visible tool labels.

The selected agent toggle uses white (#FFFFFF) text and a white logo in both themes. Step headings use the theme-specific accent ink. Codex uses #0285FF and Claude Code uses #D97757. These are the user-approved interface colours.

- Codex blue: #0285FF is the `--blue-400` value in [ChatGPT Learn’s stylesheet](https://learn.chatgpt.com/_astro/PageLayout.CV08qZUK.css), retrieved from [ChatGPT Learn](https://learn.chatgpt.com/) on 16 October 2026. That stylesheet uses it for solid information backgrounds and dark-mode focus rings and switches. This is verified interface usage, not a claim that OpenAI publishes it as Codex’s official brand blue.
- Claude Code orange: #D97757 is `COLOR_PRIMARY` in [Lobe Icons’ Claude Code style source](https://github.com/lobehub/lobe-icons/blob/master/src/ClaudeCode/style.ts), verified on 16 October 2026. The colour remains unchanged when using the Claude logo.

In light mode, all three step cards use 4% of the selected accent mixed with 96% white. Their icon tiles use 16% accent mixed with 84% white, and their icon lines use 80% accent mixed with 20% black. These sRGB mixes follow the selected agent automatically.

## Colour Themes

`website/lib/workshop-theme.mjs` supplies shared theme variables, Lucide Sun/Moon controls and an early nonce-authorised preference script for both server-rendered pages. The sun is always on the left and the moon on the right; the active button is filled and exposes its pressed state. The resources control sits beside the branding; the password control sits inside the access panel so it remains reachable while the background is inert.

The initial theme follows the operating system. An explicit choice is stored under `workshop-colour-theme`, survives page navigation and browser visits, and synchronises across tabs. If storage is unavailable, switching still works for the current page. The script applies the theme before rendering and follows device changes until a choice is made.

Dark mode uses near-black neutral surfaces, off-white text, lighter secondary text, and cards and icon tiles mixed with the selected agent accent. Accent button branding stays unchanged, the monochrome logo becomes white, and QR pixels retain their white background.

Generate both standalone previews, then run `node website/tests/theme-browser-check.mjs` with Playwright available, or set `PLAYWRIGHT_MODULE` to its absolute module location. The checks use installed Chrome and cover both agents, four viewport widths, preference persistence, keyboard access, copy behaviour, text contrast, password styling, storage denial, nonce policy and reduced motion. Open user-facing previews in Chrome.

The QR card, prompt panels and their feedback surfaces share `--content-surface`: #F8F9FA in light mode and the existing dark surface in dark mode. The QR image retains its white background. Change this variable to keep these surfaces in sync without changing password panels or button fills.

Both toggles use `createWorkshopToggle` from `website/lib/workshop-toggle.mjs` and the shared `.segmented-toggle` styles. Their outer height is 50px, with 40px buttons and shared padding and borders. Clicking either half, the centre gap or the outer track padding reverses the current state, including the selected half. The single animation controller owns a 160ms held stretch and a 360ms release animation with constant-speed travel to the overshoot, immediate direction reversal, slight squash at impact and a sharp linear first rebound followed by eased final settling; edits there affect both controls. Holding either half stretches the indicator without changing state. Added width is capped at 6px (and 14%) through the shared controller so wider app labels do not exaggerate the deformation; held translation is 4px and vertical compression is 6%. Releasing activates the other state. Space and Enter follow the same held/released sequence, and cancelled presses restore the indicator. Reduced motion cancels the animation and moves directly to the selected state.
