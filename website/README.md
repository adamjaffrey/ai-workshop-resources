## Project Tracking

This directory is the website project root. [VERSION.txt](VERSION.txt) is its sole artefact-version authority; [CHANGELOG.md](CHANGELOG.md) records website builds and [BACKLOG.md](BACKLOG.md) records unfinished website work. The changelog was moved from the repository root without changing historical entries. README revisions are independent of website builds and skill revisions. The server verifies the shared password before returning workshop content. Sessions expire seven days after login without extending on use. The persistent Secure, HttpOnly, SameSite cookie survives tab and browser closure, unless the user clears cookies or uses private browsing. Logging out revokes the current session immediately; changing the server verifier invalidates all existing sessions.

## Configuration

Keep the chosen password in the repository root's ignored `.env` as `password`. Never copy it into source, client assets, command arguments or Git. Production uses only the secret `WORKSHOP_PASSWORD_VERIFIER`, generated by `makeVerifier` in `lib/workshop-handler.mjs`, using scrypt and a random salt. Treat this verifier as secret too. Updating the local file alone does not change the deployed site: securely update the hosted secret and deploy the validated build.

`.openai/hosting.json` retains the existing Site ID and declares the D1 `DB` binding. Sites applies the checked-in Drizzle migrations during deployment. The database stores hashed random session tokens, expiry timestamps, verifier versions and short-lived attempt counters. No plaintext password or session token is stored in D1. Missing configuration or database errors deny access.

## Block Geometry Rules

### Words And Text Styles

- Replace every visible word separately, including prompt text; do not estimate widths from character counts or replace entire prompt lines with generic bars.
- Measure rendered word widths in Chrome after the page font has loaded. Retain the measured widths, original spacing, line boxes and responsive wrapping.
- Use one consistent cap height per text style, measured from capital H at that style's font family, weight and size. Align each block's bottom to the alphabetic baseline. Do not use average word height or each word's ascenders/descenders; emoji placeholders follow the same cap-height rule.
- Use invisible lowercase `x` characters only for eligible words inside prompt/code text (`pre`) and skill-slug labels (`.slug`). Do not apply this technique to every monospaced text area. A word is eligible only when every original character has the same rendered width as `x` in that text style, within the generator's tolerance of less than 0.01px per character.
- For each eligible word, retain `/` and `-` and replace every other character with `x`; preserve the original whitespace between words. Make these anonymous glyphs transparent and draw the visible cap-height blocks with CSS. The glyphs are layout scaffolding, not visible lettering or protected text hidden by blur.
- Preserve native browser wrapping with these glyphs: long prompt words, commands and skill slugs can split across lines as the viewport changes. One measured rectangle per word is unbreakable and cannot reproduce those internal line breaks. Retaining slash/hyphen punctuation preserves the corresponding native break opportunities; do not replace entire prompt lines with fixed bars.
- Use measured empty rectangles for all text outside `pre` and `.slug`, and for any word inside those areas that fails the equal-width check, including wider emoji. Measure each word in its actual font/style after fonts load; retain its measured width, spacing and line-box dimensions. Both approaches use the same cap-height and baseline rules. In Components explanatory prose, split measured filename/path rectangles at existing slash/hyphen break opportunities so those native breaks remain available; this does not extend dummy `x` glyphs beyond `pre` and `.slug`.
- Never include original protected words, commands or link destinations in the generated backdrop. Removing the blur or making the anonymous glyphs visible must reveal only measured shapes and dummy text. These eligibility and replacement rules are implemented in `scripts/measure-playground-document.mjs`, with block styling in `lib/workshop-placeholder.mjs`.

### Icons And QR Code

- Replace background SVG icons with blocks. Group the step icons, agent logos, theme icons and copy/success icons separately; match dimensions within each set using its largest measured width and height. Hidden state variants may supply dimensions but must retain hidden visibility; only the active layer is painted.
- Current set dimensions are 26×26px for step icons, 20×20px for ChatGPT/Claude logos, 20×20px for theme icons and 18×18px for copy/success icons. These describe the present layout; future layout measurements determine new values.
- Preserve each icon's layout classes, alignment, surrounding tile/button, responsive visibility and spacing. Keep the Wavelength branding image visible. Functional password-panel controls remain functional and are not replaced.
- Replace only the QR pattern with one block. Measure the original dark-pixel bounds and preserve the surrounding opaque white quiet zone. The present 540×540px source has 48px padding on each side, scaled proportionally with the image. Keep that padding white in both themes; retain the QR card, caption, border and responsive visibility.

### Colour And Blur

- Default block strength is 40%: an opaque mix of 40% foreground ink and 60% of the containing surface colour. This is a colour blend, not element or page opacity.
- Use the relevant surface for each word/icon: page, card, prompt panel, button or icon tile. Preserve those surfaces and their colours. For the QR centre, mix dark ink with white and leave its white padding untouched.
- Apply the same Block strength setting to words, icons and the QR centre. Retain the separate 4px background blur default. Do not bake strength or blur into measured geometry; changing either never requires remeasurement.

## QR Touch Preview

On touch input when the primary device cannot hover, the first tap reveals Copy Link and a second deliberate tap copies. Ignore repeat taps within 300ms of revealing the overlay. Tapping outside or leaving keyboard focus dismisses the preview; touch-related blur does not reset it. Handle valid touch releases directly, reject drag/cancel gestures and suppress compatibility clicks because Safari hover synthesis can omit or mislabel clicks. Mouse and keyboard activation remain immediate. Other controls retain single-tap activation because their hover styling does not conceal an action.

## Login Feedback

Use a fixed 18px input icon slot: neutral muted-text Lucide Lock at rest and CSS-rotated Loader Circle while checking, and green Check on success. Reduced motion keeps the spinner static. Checking and success messages remain in a visually hidden live region; only errors appear below the field, with the semantic red Lucide X. Keep status text in sentence case and button labels in CMOS title case.

Validate empty passwords inline without shaking. Only an incorrect-password response marks the supplied password invalid and shakes the panel; connection, service and request failures must not imply a password mistake. Do not expose raw server or browser exceptions. Service outages render a styled login page where possible and return structured failures for login requests.

Rate-limit feedback uses the actual remaining server window from Retry-After, rounds displayed minutes up, and says less than a minute for the final minute. Disable submission until that time ends, then announce that signing in can be retried. Update announcements only when displayed text changes, avoiding per-second screen-reader chatter.

Login status messages use the existing system font at 14px with a 21px line height, regular weight (400) for all statuses, including checking, errors, retry information and success; the submit button remains semibold (600). Leave 12px between label and field, 12px below the input border and 16px before the submit button. Reserve one line (21px at default text size) for errors in every state; permit growth for text scaling instead of clipping.
