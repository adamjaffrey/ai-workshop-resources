# Workshop Website Access

The server verifies the shared password before returning workshop content. Sessions expire seven days after login without extending on use. The persistent Secure, HttpOnly, SameSite cookie survives tab and browser closure, unless the user clears cookies or uses private browsing. Logging out revokes the current session immediately; changing the server verifier invalidates all existing sessions.

## Configuration

Keep the chosen password in the repository root's ignored `.env` as `password`. Never copy it into source, client assets, command arguments or Git. Production uses only the secret `WORKSHOP_PASSWORD_VERIFIER`, generated by `makeVerifier` in `lib/workshop-handler.mjs`, using scrypt and a random salt. Treat this verifier as secret too. Updating the local file alone does not change the deployed site: securely update the hosted secret and deploy the validated build.

`.openai/hosting.json` retains the existing Site ID and declares the D1 `DB` binding. Sites applies the checked-in Drizzle migrations during deployment. The database stores hashed random session tokens, expiry timestamps, verifier versions and short-lived attempt counters. No plaintext password or session token is stored in D1. Missing configuration or database errors deny access.

## Build And Validation

Use Node.js 24 or later for the built-in SQLite tests. This application retains the supported Sites Vinext starter and build integration. Install dependencies with `npm run install:ci`, configure the local execution profile with the Sites plugin's `configure-execution-profile.mjs`, and build with its `build-site.mjs`. Run `node --test tests/auth.test.mjs` before building.

For local Worker testing, apply `drizzle/0000_early_felicia_hardy.sql` to the local D1 database, provide a test-only `WORKSHOP_PASSWORD_VERIFIER` in ignored `dist/server/.dev.vars`, then run `npm start -- --port 8787`. The browser check uses the test password declared in `tests/auth.test.mjs`. Run `node tests/browser-check.mjs` with Playwright available, or set `PLAYWRIGHT_MODULE` to its absolute module location. The test uses installed Chrome. Rebuilds remove the local `dist/server/.dev.vars`; restore the test verifier and restart the preview after rebuilding. Remove local secret files before packaging.

The tests cover unauthorised content delivery, forged cookies, fixed seven-day expiry, password rotation, logout revocation, origin checks, request limits, rate limits, unavailable dependencies, browser restarts and mobile layout. Login attempts are limited to 50 per source IP and 1,000 globally per 15-minute window. Participants behind one shared network share the IP allowance.

## Access Boundary

This protects content delivered by this website. The linked public GitHub repository, its history and independently published files remain public. A shared password can be forwarded and does not identify individual participants. Branding assets remain public; workshop content is delivered only by the authenticated server route. Previously downloaded material cannot be withdrawn.

## Local Design Review

Run `node website/scripts/preview-login.mjs` from the repository root, then open `website/outputs/login-design-preview.html` directly in Chrome. No server is needed. Switch between No blur, Blur only and Password panel using the preview controls. The form is disabled and the file contains no credentials or protected workshop content. The generated output is ignored by Git and excluded from deployment.

The login background is generated on the server from the current resources layout and its CSS through `website/lib/workshop-placeholder.mjs`. Layout changes therefore flow through automatically, including step count, columns, spacing, colours and mobile breakpoints. Text becomes anonymous word geometry; scripts, links and non-layout attributes are removed before the login response is sent. Prompt areas use fixed dummy lines. This is an approximate decorative background, not an exact screenshot of protected content.

Development and build startup regenerate both standalone preview files; reload an already-open file after regeneration. The production login always uses the current resource layout without a separate regeneration step. Builds run the placeholder regression tests automatically. Run `node --test website/tests/placeholder.test.mjs` for source checks and `node website/tests/placeholder-browser-check.mjs` with `PLAYWRIGHT_MODULE` available for Chrome checks at four viewport widths in both themes. Unsupported new element types fail explicitly so their handling can be reviewed. Review controls exist only in the local preview. Keep design iterations local until publishing is approved.

Run `node website/scripts/preview-resources.mjs` from the repository root to generate `website/outputs/workshop-resources-preview.html`. Open this file in Chrome, not the Codex sidebar. Both images and the font are embedded so the preview works when moved. It retains the agent selector and copy controls but omits session checks and logout; production authentication is unchanged.

## Agent Logos And Colours

The agent selector pairs the ChatGPT knot logo with “Codex” and the Claude starburst logo with “Claude Code”. The inline SVGs come from [Lobe Icons’ OpenAI SVG](https://github.com/lobehub/lobe-icons/blob/master/packages/static-svg/icons/openai.svg) and [Claude SVG](https://github.com/lobehub/lobe-icons/blob/master/packages/static-svg/icons/claude.svg). Both inherit `currentColor`, remain decorative to assistive technology and retain visible tool labels.

The selected agent toggle uses white (#FFFFFF) text and a white logo in both themes. Step headings use the theme-specific accent ink. Codex uses #0285FF and Claude Code uses #D97757. These are the user-approved interface colours.

- Codex blue: #0285FF is the `--blue-400` value in [ChatGPT Learn’s stylesheet](https://learn.chatgpt.com/_astro/PageLayout.CV08qZUK.css), retrieved from [ChatGPT Learn](https://learn.chatgpt.com/) on 16 October 2026. That stylesheet uses it for solid information backgrounds and dark-mode focus rings and switches. This is verified interface usage, not a claim that OpenAI publishes it as Codex’s official brand blue.
- Claude Code orange: #D97757 is `COLOR_PRIMARY` in [Lobe Icons’ Claude Code style source](https://github.com/lobehub/lobe-icons/blob/master/src/ClaudeCode/style.ts), verified on 16 October 2026. The colour remains unchanged when using the Claude logo.

In light mode, all three step cards use 4% of the selected accent mixed with 96% white. Their icon tiles use 16% accent mixed with 84% white, and their icon lines use 80% accent mixed with 20% black. These sRGB mixes follow the selected agent automatically.

## Colour Themes

`website/lib/workshop-theme.mjs` supplies shared theme variables, Lucide Sun/Moon controls and an early nonce-authorised preference script for both server-rendered pages. The sun is always on the left and the moon on the right; the active button is filled and exposes its pressed state. The resources control sits beside the branding; the password control sits inside the access panel so it remains reachable while the background is inert.

The initial theme follows the operating system. An explicit choice is stored under `workshop-colour-theme`, survives page navigation and browser visits, and synchronises across tabs. If storage is unavailable, switching still works for the current page. The script applies the theme before rendering and follows device changes until a choice is made.

Dark mode uses near-black neutral surfaces, off-white text, lighter secondary text, and cards and icon tiles mixed with the selected agent accent. Accent button branding stays unchanged, the monochrome logo becomes white, and QR pixels retain their white background.

Generate both standalone previews, then run `node website/tests/theme-browser-check.mjs` with Playwright available, or set `PLAYWRIGHT_MODULE` to its absolute module location. The checks use installed Chrome and cover both agents, four viewport widths, preference persistence, keyboard access, copy behaviour, text contrast, password styling, storage denial, nonce policy and reduced motion. Open user-facing previews in Chrome.

The QR card, prompt panels and their feedback surfaces share `--content-surface`: #F8F9FA in light mode and the existing dark surface in dark mode. The QR image retains its white background. Change this variable to keep these surfaces in sync without changing password panels or button fills.

Both toggles use `createWorkshopToggle` from `website/lib/workshop-toggle.mjs` and the shared `.segmented-toggle` styles. Their outer height is 50px, with 40px buttons and shared padding and borders. Clicking either half, the centre gap or the outer track padding reverses the current state, including the selected half. The single animation controller owns a 160ms held stretch and a 520ms release animation with constant-speed travel to the overshoot, immediate direction reversal, slight squash at impact and diminishing linear rebounds; edits there affect both controls. Holding either half stretches the indicator without changing state. Releasing activates the other state. Space and Enter follow the same held/released sequence, and cancelled presses restore the indicator. Reduced motion cancels the animation and moves directly to the selected state.
